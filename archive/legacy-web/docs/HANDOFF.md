## 문서와 코드의 기준

- 현재 동작의 기준은 `app/` 코드다.

## 현재 게임 규칙

### 지도와 장소

- 세계는 7개 지역이며 각 지역은 212×47칸이다. 일반 지역 사이에는 바위 5줄이 있다.
- 일반 지역마다 덱 금고는 수제 지형 금고 2개를 포함해 총 18~24개를 둔다. 제단·땜장이·변환기는 합계 3개로 각각 독립적으로 1/3 확률로 정하며, 포탈은 8~12개를 배치한다. 안전구역의 보스 오른쪽에는 서로 다른 무작위 서비스 두 개를 둔다.
- 일반 상점·피의 상점·성소·보물 상자·무작위 회복/축복 노드는 일반 지도에 생성하지 않는다. 바닥 카드와 티켓도 자연 생성하지 않는다.
- 안전 지대에는 진입 칸 오른쪽의 30% 회복 지형, 전량 회복, 다음 지역 포탈이 있다. 1~3지역에는 보스가 있다. 30% 회복 지형은 사용 후 사라진다. 안전 지대에서는 보스 생존 여부와 관계없이 덱을 편집할 수 있지만 용량·희귀 슬롯 제한은 유지한다. 안전 지대 바닥에 티켓은 자동 배치하지 않는다. 두 공간 사이의 일자 통로는 9칸이며 보스는 통로 중앙에 배치한다.
- 덱 금고는 열쇠 3개로 한 번 열 수 있으며, 덱과 추출 티켓 1개가 바닥에 놓인다.
- O 자동 여행은 알려진 안전 경로로 미탐사 타일과 골드 더미를 탐사한다. 적의 인식 범위를 회피하고, 새 특수 지형을 발견하거나 안전하게 갈 목적지가 남지 않으면 멈춘다. 새 아이템만으로는 멈추지 않는다.

### 골드·보상·티켓

- 일반 전투는 열쇠 1개와 카드 1장을 준다. 미래 지역 적은 카드 대신 해당 지역 덱을 준다. 전투와 보스는 골드나 티켓을 주지 않는다.
- 보스는 스티커가 보장된 희귀 카드 2장을 준다. 보스 학살자 축복은 보스보다 한 지역 높은 덱을 추가한다.
- 일반 카드 보상의 기본 희귀 확률은 5%이고, 비희귀 카드가 나오면 다음 확률이 2%p 오른다. 희귀 카드가 나오면 5%로 돌아간다.
- 활성 티켓은 폭탄·추출·변환·복제·확장이다. 일반 플레이의 획득 경로는 덱 금고 개방 때 받는 추출 티켓 1개뿐이다. 축복 지형은 생성하지 않는다. 카드 팩은 티켓과 별개다.
- 지역마다 96~111개의 골드 더미를 두며 합계는 1,000골드다. 더미 수는 덱 금고 수와 독립적으로 추첨한다. 타일에 들어서면 추가 턴 없이 줍고, 플레이어 위에 `+N`을 표시한다.
- 일반 카드 보상과 미래 지역 보상 덱의 각 카드에는 30% 확률로 **스티커**가 붙는다. 덱 금고 카드마다 확률은 2%다. 보스 카드에는 스티커가 반드시 붙는다. 덱 에디션은 카드 스티커와 별개인 덱 단위 설정이다.

### 카드와 전투

- 파랑새는 손패→파일·파일→파일 솔리테어 이동의 별 비용을 0으로 만든다. 파일→손패 기능은 없다. 낙하산은 카드 사용 후 빈 파일로 이동하며 턴 종료·버리기 X에는 발동하지 않고 소멸을 막지 않는다.

- 카드 스티커는 월석·태엽장치·책갈피·연·닻·야광공룡·파랑새·갈고리·낙하산·혜성 10종이다. 일반 카드는 한 개, DIY는 서로 다른 스티커를 최대 세 개까지 가진다. 시작 덱에는 스티커가 없다.
- 제단·땜장이·변환기는 카드를 선택해 사용한다. 기본 가격은 제단 $100, 변환기 $40, 땜장이는 스티커 종류별 가격이며, 같은 장소의 성공 횟수마다 1.5배로 오른다. 제단은 스티커가 정확히 한 개 있는 카드만 제물로 받는다. 제물·숙주 입력 슬롯은 어느 순서로든 드래그 배치할 수 있고 오른쪽에는 결과를 미리 보여준다. 변환기는 선택 카드의 같은 희귀도 후보와 스티커 교체 결과를 오른쪽에서 0.1초마다 순환해 예시로 보여준다. 이 미리보기는 확인 시 실제 결과를 고정하지 않는다.
- 1지역 보스 청소부는 HP 150이며 약화 2+취약 2 → 피해 15 → 피해 6×2 → 피해 10+힘 3 순서로 반복한다.
- 2지역 보스 간수는 HP 250이며 저항 2+증폭 2 → 피해 20 → 피해 20 → 힘 5 순서로 반복한다. 저항·증폭 효율은 패시브로 40%다.
- 4~7지역의 적·보스 콘텐츠는 아직 비어 있다. 전설 카드도 일반 획득 경로가 연결되어 있지 않다.

## 저장과 실행

- 웹 탐험 진행은 브라우저 `localStorage`에 저장·복원된다. 전투와 덱 편집 중 상태는 저장하지 않으며, 패배 또는 새 탐험 시작 시 진행 저장을 지운다.
- 데스크톱 실행기는 Electron 정적 앱이며 웹의 localhost 서버와 별도 저장 공간을 사용한다. 실행·빌드·갱신 절차는 [desktop/README.md](../desktop/README.md)를 따른다.
- Godot 포트는 `godot/`의 기존 작업본과 GDScript를 유지한다. 대표 전투 B01~B07, 규칙 비교 63사례를 통과했다. Luna가 적의 버리기 경고와 카드 글꼴을 맞췄고, 실제 창 축소·12장 손패 이동·Space 정렬 및 첫 창 복귀·강제 버리기의 클릭 및 숫자 선택을 확인했다. 2026-11-13 실제 GUI에서 10개 파일 스택 수평 스크롤은 5/5 확인했다([보고](../outputs/godot-validation/2026-11-12-ui/file-stack-scroll-report.json)): overflow max 626px, 첫 wheel down 86px 이동, 끝까지 이동과 clamp, wheel up으로 0 복귀. 같은 날 1280×820 렌더의 4장 스택은 preview 4개, 1:1 canvas transform, 121×170px 카드 크기(웹 CSS 120.9×170), 세 간격 모두 27px, 버튼 높이 251px를 5/5 확인했다([보고](../outputs/godot-validation/2026-11-12-ui/pile-stack-report.json), [캡처](../outputs/godot-validation/2026-11-12-ui/godot-pile-stack.png)). Windows DPI 배율은 미측정이다. 2026-11-13 웹 800×480 지도 페이지는 632px, 실제 전투 페이지는 1011px였다. 전투 손패 y=743px, 턴 종료 버튼 y=947px이며 첫 화면 밖이다([지도 보고](../outputs/godot-validation/2026-11-12-ui/web-short-viewport-report.json), [전투 보고](../outputs/godot-validation/2026-11-12-ui/web-battle-short-viewport-report.json)). Godot은 같은 창 크기에서 게임을 749×480으로 축소하고 턴 종료 접근 검사를 통과했다. 전투 상태는 서로 매칭하지 않았고 C02 배치 전체는 미완료다. 전투 카드 설명 86개는 실제 위젯에서 한글 단어 단위 줄바꿈 86/86·넘침 0건을 확인했다. 폰트 계열·다른 화면은 미확인이라 C01은 미완료다. 강제 버리기 대기 중 Escape는 선택을 유지하고, 키보드 드래그 중 Escape·우클릭 취소도 기존 GUI 입력에서 확인했다. E 턴 종료는 연속 입력 1회 종료와 pending draw 중 차단을 확인했다. 강제 버리기 숫자키 선택 후 Enter/키패드 Enter는 선택만 해제하고 pending 수량과 discard를 유지했다([5/5 보고](../outputs/godot-validation/2026-11-12-ui/discard-enter-report.json)). 대상 카드 더블클릭은 선택 ID와 안내를 설정하고, Enter·키패드 Enter는 일반 선택 상태를 바꾸지 않았으며, 적 클릭은 선택 소비 후 해당 카드 사용을 확인했다([5/5 보고](../outputs/godot-validation/2026-11-12-ui/target-selection-report.json)). 숫자키·Escape·Space·E·강제 버리기를 포함한 Windows PC 입력 확인으로 C03은 완료했다. 모바일 단일 클릭 선택은 범위 밖이다. 2026-11-13 분리 Godot 4.7.2 GUI probe 6/6에서 정지 클릭 tile 신호 1회, 바닥 카드 아이콘 클릭 pickup 1회, 12px 지도 pan tile 신호 0회, 같은 아이콘 방향 pan pickup 0회, 휠 위·아래 줌만 변경, 5.5px 이동 클릭을 확인했다. 5.5px 차이를 재현해 Godot 임계값을 웹 기준 >6px로 맞췄다. 이는 C04의 해당 입력 항목만 확인했으므로 C04는 미완료다. C01·C02·C04를 포함한 전체 포트도 미완료다. 강제 버리기 숫자키는 현재 웹처럼 선택·전환·해제만 하며 확정하지 않는다. 다른 보조 입력 검증은 계속 남아 있다. 포팅 범위와 결과는 [포팅 체크리스트](GODOT_PORT_CHECKLIST.md), 작업본·언어 결정은 [포팅 검토](GODOT_PORT_REVIEW.md)를 따른다.
- C01 후속: 전투 중 방어량 설명의 공백을 복원하고, 실제 카드 위젯 배치 뒤 86개 설명의 단어 경계 줄바꿈을 확인했다. 이후 웹의 `PretendardVariable.woff2`를 Godot 공유 카드 위젯 제목·본문·강조, 덱 편집과 검색 결과 작은 카드의 이름, 전투 파일·카드 효과 예시의 작은 미리보기 이름·설명에 연결했다([폰트 작업 기록](GODOT_SOL_C01_FONT_ASSET.md), [작은 미리보기 보고](../outputs/godot-validation/2026-11-12-ui/c01-font-asset-sol/compact-preview-font-report.json)). 새 폰트로 전투 카드 위젯 86개를 다시 확인한 결과 텍스트 손실·높이 넘침은 0건, 최대 내용 높이는 105/143px이었다([실제 위젯 보고](../outputs/godot-validation/2026-11-12-ui/c01-font-asset-sol/card-description-integration-report.json)). 다른 카드 표시 화면·실제 글리프 폴백·모든 동적 수치 상태는 미확인이라 C01은 미완료다.
- C02 창 축소 기준은 사용자가 정했다: 800×480 같은 작은 PC 창에서 전투 전체를 비율에 맞춰 축소하고 턴 종료 버튼을 화면 안에 둔다. C02의 다른 배치 확인은 계속 남아 있다.
- C05 후속에서 작은 카드의 테두리·상단 띠·글꼴·스티커·중복 수 배지를 코드에 반영한 뒤, Sol이 최대 5개·7px 간격의 겹침 뒷면과 띠를 추가했다. 전면의 82×82 입력 영역을 유지하며 격리 Godot GUI 렌더/입력 probe 16/16과 편집 화면 캡처를 확인했다. Luna가 작은 카드·스택의 전설 띠를 CSS `#d5a928`으로, 긴 이름의 넘침을 강제 말줄임표로 맞췄다. 두 후속 변경의 새 렌더 확인은 하지 않았다. 같은 상태의 웹 렌더 픽셀 대조와 전면 외형 비교가 남아 C05는 미완료다. [기록과 캡처](GODOT_SOL_C05_LAYOUT.md).

C05-08에서는 누락된 덱→바닥 드롭을 연결하고 안전 구역의 즉시 이동과 일반 지역의 제거 예약→편집 종료 후 바닥 배치를 실제 GUI 드래그로 확인했다. 예약 카드 표시와 안내도 확인했다. 희귀 카드의 임시 인벤토리·바닥 출처 복귀, 인벤토리 포화 시 바닥 복귀, 원래 덱 희귀 카드 제거 예약과 합성 `forbiddenKnowledge` 조건은 직접 callback으로 확인했다([C05-08 기록](GODOT_SOL_C05-08.md), [21/21 보고](../outputs/godot-validation/2026-11-12-ui/c05-08-sol/c05-08-report.json)). C05-09에서는 카드 25장으로 찬 덱 B에 인벤토리 카드를 실제 GUI 드래그해 거부·상태 불변과 용량 초과 안내를 확인했다([9/9 보고](../outputs/godot-validation/2026-11-12-ui/c05-09-luna/c05-09-report.json)). C05 전체는 미완료다. Godot에는 축복 획득·저장 및 웹의 티켓 변환 해제 상태가 없어 실제 플레이의 해당 동등성은 아직 확인할 수 없다. 물리 마우스와 나머지 희귀·용량·배치 경로도 남아 있다.
- C05 배치 후속: Godot 덱 편집 화면의 1280×820 컨트롤 좌표를 웹 측정에 맞췄다. 패널 `(14,108,1252×604)`, 인벤토리 `(14,108,1252×104)`, 첫 덱 행 `(14,244,1252×104)`, 바닥 `(14,608,1252×104)`이며 가로 콘텐츠 넘침 probe에서도 카드 행은 104px를 유지했다([측정 보고와 한계](GODOT_SOL_C05_LAYOUT.md)). 좌표 측정은 렌더링 캡처가 아니므로 카드 모양·색·실제 GUI 화면 대조가 남아 C05 전체는 미완료다.
- 사용자 플레이 항목: PT-001은 Luna가 `main.gd`의 0.02초 지도 이동 반복을 제거하고 OS 반복 키 이벤트로 이동하도록 수정했다. Sol이 소스와 합성 입력 검사(단일 입력·echo·키 해제·동작 echo 차단·이름 입력창 차단)를 확인했으며 실제 Windows 키보드 감각은 플레이 확인 대기다. PT-002 패배 후 재시작 정지/로딩 안내(H05·G03), PT-003 지도 상단의 위쪽 타일(C04·D01·D03)은 대기·재현 전이다.
