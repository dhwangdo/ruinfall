# 맵 개편

2026-11-02. 사용자가 선택한 **혼합형 · 공터 일부**를 실제 게임에 적용했다.

실제 게임은 [localhost:3000](http://localhost:3000/)에서 확인한다. [기존 네 방식 비교](http://localhost:3000/map-preview.html)는 설계 과정의 정적 시안으로 보존하며 실제 생성기의 현재 시드·포탈 개수·수제 지형 위치와는 별개다.

## 합의한 방향

- 지역 크기는 321×31칸. 2026-11-02 깊이를 15→41칸으로 늘린 뒤 2026-11-03에 10칸 줄였다. 가로·7개 지역·사이의 바위 5줄·안전 지대·보스·포탈 이동 흐름은 유지한다.
- 큰 벽 덩어리 사이의 좁고 굽은 길·갈림길·우회로를 만들고 길의 폭과 거칠기를 연속적으로 바꾼다. 연결점마다 명확한 공터를 만들지 않고 일부만 작은 공터로 복원한다.
- 삐죽한 막다른 가지와 작은 고립 바닥을 허용한다. 플레이어의 영역이 압도적으로 큰 메인 대륙이어야 하며 포탈·수제 지형의 출입구와 지정 장소에는 도달할 수 있어야 한다.
- 현행 8방향 이동·모서리 통과를 유지한다. 기둥 금고의 바둑판 모양도 이 이동 규칙을 사용한다.
- 일반 장소는 지역별 목표 개수로 생성한다. 필드 금고 40~46개·상점 3~4개·피의 상점 3~4개·포탈 14~18개를 각각 범위 안에서 균등 추첨한다. 벽과 고립 바닥에는 일반 장소를 놓지 않는다. 수제 지형의 지정 장소는 **일반 생성분에서 차감하지 않고 별도로 추가**한다.
- 사용자가 계속 수제 지형을 추가할 수 있도록 생성 코드와 지형 데이터를 분리한다. 스케치의 소용돌이 금고·기둥 금고는 초기 예시일 뿐 최종 목록이 아니다.
- 참고 스케치는 references/map-layout-sketch.png다. 검정은 벽, 투명한 부분은 길, 주황은 금고, 갈색은 상점, 빨강은 피의 상점, 보라는 포탈이다.
- 개발 저장은 필요할 때 초기화해도 된다는 사용자 허용에 따라 저장 봉투는 버전 6이다. 31칸 지도 축소 이전 탐험은 복원하지 않으며 새 탐험의 자동 저장·복원과 별도 환경설정은 유지한다.

## 실제 생성 순서

1. 지역을 벽으로 시작하고 별도 안전 지대의 고정 영역을 예약한다. 기존 규칙으로 정한 시작점·포탈 주변도 수제 지형과 겹치지 않게 예약한다.
2. 수제 지형을 먼저 가중 추첨·배치한다. 내부와 완충 영역은 이후 굴착에서 보호하고 지정 출입구만 외부 길에 연결한다.
3. 출입구·시작점·포탈·흩어진 연결점으로 최소 연결망을 만든 뒤 우회 연결을 추가한다. 위치별 굴착 비용을 주는 A*로 통로를 판다.
4. 연결점과 독립적인 공간 노이즈로 통로 폭을 바꾸고 일부 공터 후보·짧은 가지를 섞는다. 생성 중 수제 지형의 벽을 뚫어 연결을 복구하지 않는다.
5. 8방향 탐색으로 플레이어의 메인 대륙을 계산하고 필수 장소·출입구 접근성을 검사한다. 작은 고립 바닥을 더하되 메인 대륙 비중을 검사한다.
6. 일반 장소마다 목표 개수만큼 가로 구간을 나누고 각 구간의 메인 대륙 바닥에서 하나씩 고른다. 같은 종류는 6칸·다른 장소는 3칸 이상 떨어진 후보를 우선한다. 구간 안에 이 간격을 만족하는 후보가 없으면 가까운 다른 빈 바닥을 찾고, 전체에도 없을 때만 간격을 완화한다. 시작점·포탈·수제 지형 예약 칸을 덮지 않으며 수제 지정 장소는 목표 개수에 별도 추가한다.
7. 탐험 중 기존 콘텐츠 생성 흐름으로 적·바닥 물품·금고 덱을 생성한다. 일반 적은 유효한 메인 빈칸에 4%, 바닥 물품은 0.5%다. 고립 바닥에는 일반 콘텐츠를 생성하지 않는다. 폭탄의 플레이 중 바위 파괴는 기존 규칙을 따른다.

기본 지형은 시작·불러오기·새 탐험의 로딩창 아래에서 7개 지역을 프레임별로 미리 생성해 캐시한다. 저장이 있으면 저장 시드를 먼저 골라 임시 무작위 지도를 중복 생성하지 않는다. 탐험 기억·적 이동·폭탄으로 열린 칸·소비한 장소 등은 별도 게임 상태다. 일반 콘텐츠는 탐험에 따라 생성하고 디버그는 현재 지역을 512칸씩 나눠 준비한다.

### 현재 조정값

app/game/mapRegionGenerator.ts의 HYBRID_MAP_CONFIG에 모았다. 첫 적용의 조정 가능한 기본값이다.

| 항목 | 값 |
|---|---:|
| 공터 후보 중 복원 비율 | 28% |
| 연결점 수 대비 추가 연결 후보 비율 | 45% |
| 메인 대륙 목표 비중 | 전체 바닥의 약 97% |
| 메인 대륙 최소 비중 | 90% |
| 지역당 수제 지형 수 | 2개 |

현재 두 지형은 각각 지역당 최대 1개이므로 둘 다 한 번씩 배치한다. 첫 적용의 21개 지역 표본에서 바닥은 전체 격자의 약 26~30%, 메인 대륙은 전체 바닥의 약 97%였다. 비율은 각 시드의 실제 통로에 따라 달라진다. 포탈은 지역마다 14~18개를 뽑고 가로 구간마다 하나씩 놓아 몰림을 줄인다. 위치는 마지막 줄에 고정하지 않고 현재 31칸 지도에서는 깊이 2~30에서 `(깊이+1)²` 가중치로 아래쪽에 집중시킨다. 안전 지대와 수제 지형을 침범하지 않으며 모든 포탈을 통로에 연결한다.

장소 개수는 mapLocationPlacement.ts의 REGION_LOCATION_COUNTS에서 조절한다. 필드 금고 40~46개에 수제 금고 2개를 더해 지역당 총 42~48개이며, 상점·피의 상점은 각각 3~4개, 포탈은 14~18개다. 종류별 가로 구간에 분산 배치한다.

안전 지대에는 회복·축복을 복원했고 추출 성소 대신 바닥 티켓 2개를 지역마다 한 번 제공한다. 디버그는 현재 지역 전체 콘텐츠를 생성하고 최소 줌을 6.25%까지 허용하며 일반 플레이의 발견 기억과 타일 화면 범위 최적화는 유지한다.

## 화면과 입력 성능

전체 세계 크기의 DOM 격자 대신 화면 주변만 로컬 좌표 격자로 그린다. 타일·적·플레이어 표식의 원점을 함께 옮기고 화면 밖 표식도 제외한다. 원점이 바뀔 때 이전 좌표와의 보간을 끊는다. 같은 타일은 다시 만들지 않으며 이동과 카메라 갱신을 같은 배치에 반영한다. 닫힌 적 도감의 전체 목록은 그리지 않는다.

지형 준비 중에는 진행률을 표시하고 이동 입력을 막으며 지도판 자체는 그리지 않는다. 기본 지형 준비는 mapPreparation.ts, 디버그 콘텐츠 준비는 useDebugMapContent.ts가 담당한다. 개발 중 ?profileMap=1로 MapPerformanceProbe 계측을 켤 수 있다.

## 수제 지형 추가

app/game/mapPrefabDefinitions.ts의 MAP_PREFAB_DEFINITIONS 배열에 데이터를 추가한다. 별도 생성 함수나 ID별 분기를 만들지 않는다.

~~~ts
{
  id: "small-vault",
  name: "작은 금고",
  grid: ["###", "#V.", "###"],
  entrances: [{ x: 2, y: 1, direction: "E" }],
  rotations: [0, 90, 180, 270],
  mirror: true,
  padding: 1,
  weight: 1,
  maxPerRegion: 1,
  // regions: [1, 2],
}
~~~

- 좌표는 왼쪽 위 (0,0)부터 센다. #는 벽, .은 바닥, V/S/B/P는 금고·상점·피의 상점·안전 지대 포탈이다. 공백은 바닥으로 파지 않는 예약 영역이다. 모든 행의 길이가 같아야 한다.
- 출입구는 격자 외곽의 바닥 칸이며 N/E/S/W 방향으로 바깥을 향한다. 변형 시 지형·장소와 출입구 좌표·방향도 함께 변환한다.
- padding은 최소 1칸이다. 내부와 완충 직사각형은 생성 중 보호하고 출입구에서만 외부로 관통한다. 다른 지형·안전 지대·시작점·포탈과 겹치는 배치는 거절한다.
- regions는 1부터 시작하는 지역 제한이며 생략하면 모든 지역이다. weight는 지형 선택의 상대 가중치, maxPerRegion은 한 지역에서의 최대 등장 수다. 일반 장소의 지역별 목표 개수와 별개다.
- 모든 출입구·지정 장소는 지형 내부에서 8방향 이동으로 연결되어야 한다. 장식적인 일반 바닥의 작은 고립 부분은 허용한다.
- 잘못된 데이터는 지형 ID와 원인이 있는 오류를 낸다. 위치가 맞지 않으면 최대 128회 다른 위치·변형을 시도한 뒤 건너뛰고 skippedPrefabs에 ID를 남긴다. 벽을 임의로 고치지 않는다.
- 각 출입구에 완충 영역 바깥의 연결 지점을 만들어 필수 연결망에 포함한다. 두 출입구 지형의 한쪽만 연결하고 끝내지 않는다.

## 참고한 1차 자료

- [Bob Nystrom, Rooms and Mazes](https://journal.stuffwithstuff.com/2014/12/21/rooms-and-mazes/): 연결망과 우회로, 과한 방·길 구분에 대한 한계.
- [Dungeon Crawl Stone Soup 지형 제작 문서](https://github.com/crawl/crawl/blob/master/crawl-ref/docs/develop/levels/introduction.txt): 수제 지형 우선 배치, 명시적 출입구와 접근성 조건.
- [Zorbus Dungeon Generator](https://dungeon.zorbus.net/): 문자 격자 수제 지형 데이터 분리.
- [Two-step Constructive Approaches for Dungeon Generation](https://arxiv.org/abs/1906.04660): 벽·바닥 생성과 콘텐츠 배치의 분리.
- [Cogmind, Mapgen: Tunneling Algorithm](https://www.gridsagegames.com/blog/2014/06/mapgen-tunneling-algorithm/): 굴착 중 폭과 방향 변화.
- [Red Blob Games, Making maps with noise functions](https://www.redblobgames.com/maps/terrain-from-noise/): 서로 다른 공간 크기의 노이즈 조합.
