# F01 카드 메타데이터 1차 대조

작성일: 2026-11-13  
범위: 웹·Godot의 카드 기본 풀 메타데이터, 일반 보상 풀 분류와 토큰 비용 표기. 카드 효과의 실제 실행은 검증하지 않았다.

## 결과

| 웹 풀 | 웹 수 | Godot 풀 | Godot 수 | 판정 |
|---|---:|---|---:|---|
| 시작 | 2 | `STARTER_CARDS` | 2 | 이름·분류·비용 일치 |
| 기본 | 8 | `BASIC_CARDS` | 8 | 이름·분류·비용 일치 |
| 특별 활성 | 46 | `SPECIAL_CARDS` | 46 | 이름·분류·비용 일치 |
| 희귀 | 26 | `RARE_CARDS` | 26 | 이름·분류·비용 일치 |
| 전설 | 6 | `LEGENDARY_CARDS` | 6 | 이름·분류·비용 일치 |

활성 풀 88장의 이름과 풀 소속은 전부 대응하고 중복 이름은 없다. 희귀도, 카드 종류, 비용 존재 여부와 값도 모두 같다. 정적 카드 정의에는 고정 ID가 없다. 웹과 Godot 모두 카드 인스턴스를 만들 때 ID를 부여하므로 이름과 풀을 대응 기준으로 삼았다.

웹의 `ALL_CARD_BLUEPRINTS`는 활성 88장에 레거시 특별 카드 `무쇠 난동`을 더해 89장이다. Godot의 다섯 기본 풀에는 이 레거시 카드가 없다. 웹의 임시 제외 카드 5장(`마도서`, `천문학 연구`, `강령학 연구`, `응수`, `반전`)도 현재 Godot 기본 풀에는 없다. 토큰 카드 생성 함수는 기본 획득 풀과 분리되어 있다. 디자인 문서의 디버그 덱 수에 포함된 고정 토큰 5종과 별개로 `광채`도 플레이 중 생성되는 토큰이다. 전설 6장은 두 코드에 정의되어 있지만 일반 전투 보상이나 발견 덱 생성 풀에는 들어가지 않는다.

## 남은 데이터 대응 검토

- 웹은 camelCase, Godot은 snake_case를 써서 효과 키 48개가 원문 그대로는 다르다. 이 중 46개는 단순한 표기 변환이다.
- `책 펼치기`: 웹 `drawEachPile`은 `drawFromPiles`, Godot `draw_each_file`은 `_draw_from_each_file`로 연결된다. 양쪽 코드 모두 차단되지 않은 비어 있지 않은 각 파일에서 맨 위 카드를 뽑는다. 키 이름만 다르며 소스 수준의 처리 범위는 대응한다.
- `5연격`: 웹 `fourHit` / Godot `five_hit`. 키 이름은 다르지만 두 전투 코드 모두 카드 기본 공격을 5회 반복한다. 소스 비교 결과이며 실제 전투 실행 probe는 하지 않았다.
- 특별·희귀 풀은 카드 집합은 같지만 배열 순서가 다르다. 각 풀 안에서 균등 선택하므로 획득 확률 분포는 같다. 같은 난수 인덱스를 카드 정체성에 직접 대응시키면 결과는 다르다. 웹 일반 전투 보상은 `Math.random()`을 쓰고 Godot은 전달된 `RandomNumberGenerator`를 쓰므로, 일반 보상의 같은 시드 카드 결과는 현재 양쪽에 공통 계약으로 존재하지 않는다. 배열 순서를 바꾸지 않았다.

일반 전투 카드 보상 코드는 출처상 대응한다. 기본 5% 희귀, 비희귀 카드 중 기본 30%·특별 65%이며 각 풀에서 균등 선택한다. 보스 보상은 희귀 카드 2장과 스티커 100%다. 지역 덱은 두 코드 모두 시작·기본·특별 필러와 80% 희귀 슬롯을 사용한다. 이 내용은 생성 함수의 조건을 대조한 것이며, 각 생성 규칙의 난수 결과 전체를 재현한 검증은 아니다.

## 토큰 카드 비용 표기

웹과 Godot은 `돌`, `흙`, `유독성 점액`, `발효 점액`, `유물`, `광채`를 별도 생성 함수에서 만든다. 웹은 `slime`·`soil`·`rock`을 `UNPLAYABLE_CARD_EFFECTS`로 막고, Godot은 대응 카드에 `playable: false`를 둔다. 웹은 흙·유독성 점액에 `cost` 필드를 두지 않아 카드에 `—`를 표시한다. Godot은 두 카드에 `cost: 0`을 넣어 `0`으로 표시하고 있었다. 웹의 `Card` 타입은 비용 없음(undefined)과 0코스트를 구분하고 Godot UI도 이 필드 유무를 표시하므로, Godot에서 두 필드를 제거해 표기를 맞췄다. 토큰 생성 함수를 추출해 이름·효과·희귀도·종류·비용·값·공개·토큰/적 토큰·보존·사용 가능 여부를 비교했다. `fermentedSlime`/`fermented_slime` 효과 키 표기 외에 이 필드 차이는 없다. Godot 4.7.2 격리 headless 추출 종료 코드 0. 토큰 효과·적 생성 시점·턴 종료 처리는 검증하지 않았다.

## 문서와 코드 차이

`docs/GAME_DESIGN.md`는 희귀 풀을 25장, `ALL_CARD_BLUEPRINTS`를 88장으로 적고 있었지만 현재 웹 코드의 희귀 풀에는 목록에서 빠진 `DIY`가 있어 각각 26장과 89장이다. 코드 기준으로 문서 수를 바로잡았다.

## 방법과 한계

웹 `app/game/cards.ts`를 Node에서 읽고, 복사된 격리 Godot 프로젝트의 `card_catalog.gd` 상수와 생성 함수를 Godot 4.7.2 headless에서 추출해 이름별로 비교했다. 검사 자료는 [비교 JSON](../outputs/godot-validation/2026-11-13-ui/f01-card-data-luna/card-pool-comparison.json)과 [웹 풀 JSON](../outputs/godot-validation/2026-11-13-ui/f01-card-data-luna/web-card-pools.json)이다. 추출기와 JSON은 격리 산출물이며, 생산 코드 변경은 Godot 흙·유독성 점액의 비용 필드 삭제 2곳뿐이다.

카드·보상·토큰 기록에 더해 [1지역](GODOT_LUNA_F01_REGION_ONE_ENEMIES.md), [2지역](GODOT_LUNA_F01_REGION_TWO_ENEMIES.md), [3지역](GODOT_LUNA_F01_REGION_THREE_ENEMIES.md) 적 목록·체력 대조를 별도로 남겼다. 카드 효과의 실제 실행, 적 행동의 실제 실행, 레거시/제외 카드의 이전 저장 처리, 토큰의 실제 생성 시점·제거 처리, 스티커·에디션 목록은 확인하지 않았다. 따라서 F01과 F06은 미완료다.
