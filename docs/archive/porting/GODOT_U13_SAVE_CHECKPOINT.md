# U13 저장점과 임시 F5 복원

상태: **저장 경계/F5 격리 GUI 17/17 · Godot 4.7.2 종료 코드 0**

## 브라우저 기준과 원인

- `app/page.tsx`의 `useRunPersistence` 허용 조건은 이름 입력 종료·지도 화면·이동 중 아님·덱 편집 중 아님이다.
- `app/hooks/useRunSaveLifecycle.ts`는 저장 허용 조건이 거짓이면 현재 상태를 파일에 쓰지 않는다. 따라서 전투 중 종료하면 이전 탐험 저장이 남는다.
- Godot은 플레이어 또는 적이 이동해 충돌한 뒤 `_start_battle_now()`와 전투 전 덱 선택 확정에서 `_save_run()`을 호출했다. 실제 전투 상태는 저장하지 않으면서 충돌 좌표와 탐험 상태만 저장해, 복원된 지도에서 적과 플레이어가 겹쳤다.

## 변경

- 전투 진입과 덱 선택 확정의 저장을 제거했다. 전투·덱 선택·보상 화면 및 활성 덱 편집/이름 입력 중 저장도 차단한다.
- 승리 보상은 지도 복귀 후 저장한다. 보상 화면에서 종료해도 전투 이전 탐험 저장을 유지한다.
- 이전 버전이 이미 적과 겹친 상태를 저장한 경우, 복원 직후 기존 조우 경로를 호출한다. 저장되지 않은 이전 좌표를 추측해 만들지 않는다. **기존 파일로 전투 전 위치를 소급 복구하는 기능은 아니다.**
- 사용자의 별도 임시 요청으로 F5를 연결했다. 현재 씬을 새로 만들어 기존 시작 시 저장 복원 경로를 사용하므로 미저장 UI 상태와 이전 비동기 callback을 함께 버린다. 저장이 없으면 새 탐험을 만들지 않고 안내한다.
