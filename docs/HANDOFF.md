# 프로젝트 인수인계 보고서

마지막 갱신: 2026-07-25

## 한 줄 요약

이 프로젝트는 **솔리테어처럼 여러 파일에 쌓인 카드를 조작하면서 싸우고, 무한 평면처럼 보이는 그리드 지도를 탐험하는 싱글 플레이 웹게임 프로토타입**이다.

현재는 전투, 지도, 덱 케이스, 덱 편집, 전투 보상, 상점, 소모품까지 한 브라우저 안에서 동작한다. 다음 큰 작업은 **지역에 따라 다양한 적을 추가하고 적 시스템을 확장하는 것**이다.

## 지금 어디까지 동작하는가

- 지도에서 방을 클릭해 이동할 수 있다.
- 이미 방문해 안전하게 연결된 방은 여러 칸 떨어져 있어도 자동 경로로 이동한다.
- 플레이어 주변 3×3만 밝혀지며, 고정 노드는 밝혀지는 순간 종류를 알 수 있다.
- `?` 방은 들어갈 때 빈 방 또는 전투로 결정된다.
- 전투가 시작되면 덱이 5장씩 파일에 배치되고, 각 파일 맨 위 카드를 손으로 가져온다.
- 카드 사용, 파일 간 묶음 이동, 손패에서 파일로 이동, 별 자원이 동작한다.
- 전투가 끝나면 지도 방 바닥에 카드·소모품·덱 케이스 보상이 남을 수 있다.
- 덱 편집, 덱 보기, 상점, 회복 노드, 안전 지역, 포탈이 동작한다.
- `main` 브랜치에 push하면 GitHub Pages 자동 배포를 시도한다.

## 기술 상태

| 항목 | 현재 상태 |
|---|---|
| 언어 | TypeScript, CSS |
| 화면 기술 | React 19 + Next.js 16 |
| 로컬 개발 실행기 | Vinext/Vite |
| 영구 저장 | 없음 |
| 서버/API | 게임 기능에는 사용하지 않음 |
| 데이터베이스 | 예제 파일만 있고 게임에는 사용하지 않음 |
| 핵심 코드 | `app/page.tsx` 약 3,334줄 |
| 핵심 스타일 | `app/globals.css` 약 2,055줄 |
| 자동 검사 | ESLint, 빌드, 서버 렌더링 테스트 |
| 배포 | GitHub Pages |

가장 큰 기술 부채는 지도, 전투, 드래그, 보상, 덱 편집 화면이 거의 모두 `app/page.tsx` 하나에 들어 있다는 점이다. 새 적을 소수 추가하는 것은 그대로도 가능하지만, 적이 계속 늘어날 예정이라면 먼저 적 데이터와 전투 규칙을 별도 파일로 나누는 편이 안전하다.

## 다음 작업: 적 시스템

현재 적은 테스트용 두 마리뿐이고 체력은 모두 `1`이다.

- 훈련용 괴수: 방어로 막는 공격 6 → 방어로 막는 공격 8 → 마법 방어로 막는 공격 5
- 숲 고블린: 마법 방어로 막는 공격 5 → 방어로 막는 공격 7 → 마법 방어로 막는 공격 9

두 적은 고정된 공격 배열을 순환한다. 열정과 각성 시스템은 사용자 결정으로 삭제되었다.

적 시스템을 확장하기 전에 정할 가치가 큰 질문은 다음과 같다.

1. 지역마다 어떤 적 풀이 등장하는가?
2. 한 전투에 적이 몇 마리까지 등장하는가?
3. 공격 이외에 방어, 강화, 약화, 상태이상 같은 행동을 허용할 것인가?
4. 적의 다음 행동을 항상 정확히 보여줄 것인가?
5. 테스트용 체력 `1`을 어떤 기준으로 정상화할 것인가?
6. 같은 적도 지역에 따라 수치만 강해질지, 강화 패턴을 새로 가질지?

다음 작업에서는 이 질문을 한꺼번에 구현하기보다, 먼저 사용자가 원하는 적 3~5종과 행동 문법을 정한 뒤 데이터 구조를 만드는 것이 좋다.

## 확인된 불일치와 주의점

- 사용자는 과거에 `예비`를 “2장 뽑고 2장 버리기”로 바꾸자고 요청했지만, 현재 코드는 여전히 **1장 뽑고 1장 버리기**다. 다음에 카드 정리 작업을 할 때 의도를 다시 확인해야 한다.
- README에 남아 있던 “각성 패턴” 표현은 오래된 설명이라 이번 문서 작업에서 제거했다.
- 체력 `1`인 적은 밸런스가 아니라 지도와 전투 전환을 빠르게 시험하기 위한 임시 설정이다.
- 게임 상태를 저장하지 않으므로 새로고침하면 진행이 초기화된다.
- 맵은 큰 유한 배열로 만들지만, 플레이어에게는 넓은 평면처럼 보이게 설계되어 있다.
- 최근 GitHub Pages 실행 일부는 GitHub runner의 `startup_failure`로 실패했다. 로컬 빌드 성공 여부와 공개 사이트 반영 여부를 따로 확인해야 한다.

## 안전한 다음 개발 순서

1. 적 기획을 짧은 표로 확정한다.
2. `EnemyState`, `EnemyAttack`, `createEnemies()`를 `app/game/enemies.ts` 같은 파일로 분리한다.
3. 공격만 표현하는 `EnemyAttack`을 여러 행동을 표현하는 형태로 확장한다.
4. 지역 번호를 받아 적 조합을 생성하는 함수를 만든다.
5. 전투 턴 처리에서 새 행동을 하나씩 지원한다.
6. 적 체력과 피해를 테스트하고 UI 의도를 확인한다.
7. 기존 지도/덱 편집 회귀 테스트를 실행한다.
